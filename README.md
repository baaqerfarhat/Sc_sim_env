# Sc_sim_env

A planar 3-DOF spacecraft simulator built to test two unvalidated claims from
*Multimodal Context Learning for Actuation and Perception Fault-Tolerant Model Predictive
Control*: the behavioural-supervision gain and the numerical recovery certificate.

The simulator is written as a replica of the deployed flight stack rather than a
clean-room model of the same physics. Where the Jetson code does something unusual, the
simulator reproduces the unusual thing — the 0.40 duty ceiling, the 5% tiny-axis zeroing,
the 12 ms minimum valve on-time, the 0.5 s position filter that is hardcoded while a 0.4 s
parameter sits unused, and the yaw share that turns a declared 2 N·m cap into an actual
0.80 N·m. Every constant in `scsim/config.py` carries a provenance tag — 24 CONFIRMED from
the deployment source, 4 OPEN, 7 SIM, and 1 **DISPUTED** (the deployed MPC horizon: the
manuscript says 10, the build spec says 12, and neither has been checked against the flight
configuration for the reported logs, so both are run and reported). The whole configuration
is hashed into every result file.

**Read [`results/results.md`](results/results.md) first.** It describes the environment,
maps every number to a paper claim, and states plainly which claims the study does and
does not support.

The review this campaign responds to is
[`results/RAL_Updated_Results_Retention_and_Completion_Plan.md`](results/RAL_Updated_Results_Retention_and_Completion_Plan.md),
and the point-by-point reply to it is
**[`results/response_to_retention_plan.md`](results/response_to_retention_plan.md)** — one
entry per plan section, marked VERIFIED / IMPLEMENTED / PARTIAL / NOT IMPLEMENTED, generated
from the artefacts. `results_v1_archive/` holds the first campaign and is marked superseded —
do not cite it.

## Findings

Run `v3-contract-and-ablation`, commit `a9ca1172`, config `07f277768a04859a`. 3840 rollouts over 60 matched scenario draws per condition x 3 training seeds.

*This section is generated by `stage9_writeup.py`. Do not hand-edit: earlier hand-written
summaries drifted from the artefacts and advertised conclusions the data had already
overturned.*

### Supported

- **Inferring a *changing* context helps (M2 vs M1):** -0.437 to -0.065 m post-onset RMSE; significantly better in 4/4 conditions, significantly worse in 0/4. This is the clean isolation: neither side carries the behavioural loss.
- **The learned residual helps (M3 vs M0):** -0.293 to -0.026 m post-onset RMSE; significantly better in 2/4 conditions, significantly worse in 0/4.
- **No conclusion depends on the disputed horizon.** The manuscript states N=10 and the build spec N=12; neither was verified against the flight configuration, so both were run. Largest paired difference 0.0138 m, not significant in 2/2 conditions.

### Not supported

- **The behavioural-supervision gain (M3 vs M2), the paper's primary claim.** It is *adverse*: +0.045 to +0.138 m, significantly worse in 4/4 conditions. The pre-declared lambda_I grid also selected **zero**, so the positive-weight model is an ablation rather than the selected method.
- **The post-allocation decrease test of Eq. (18) (M3 vs M4).** As a true single-component ablation its effect is **exactly 0.00000 m in all four conditions**: it never rejects a candidate. The eta-free first-action condition is the same inequality without the allowance, so it is strictly tighter and screens out everything the decrease test would catch. An earlier campaign reported this check as the largest effect measured; that came from three safeguards being disabled at once.
- **MPC planning beyond the fallback (M3 vs M5).** -0.033 to +0.066 m: deleting the optimiser and keeping the checked fallback changes little.
- **The numerical recovery certificate.** 0 of 2730 swept cells certify, now with a *sound* enclosure. The residual admissibility analysis did **not** run this campaign (`residual: {}`), so the empty region cannot be attributed to residual Lipschitz growth.
- **The declared task specification.** Reaching the *final* waypoint within 0.15 m and 5 deg and holding it 2 s happens in only 107/3840 rollouts across all methods. The evaluated controllers rarely achieve it; that is not evidence it is unattainable in principle.

### What the evaluated policy actually is

Worth stating plainly, because it conditions every row above: under M3 the fixed velocity-damping supervisor issues 42%-66% of transmitted actions, the eta-free first-action condition diverts a further 24%-41%, and the MPC candidate is transmitted on only 8%-13% of samples. What the table scores is largely a fixed feedback law, not context-conditioned MPC.

### Known gaps, not yet implemented

- One canonical `f_theta` evaluator shared by training, feedforward, horizon prediction, affine construction and checking; the feedforward is still nominal and its learned residual is computed and discarded.
- One verified and calibration-accepted recovery case.
- Diagnostics for supervisor dominance and the held-out-reference failure.

## Running it

```bash
python -m venv .venv && .venv/bin/pip install -r requirements.txt
python run_all.py --list     # stages, costs, and which are gates
python run_all.py            # everything, stopping at the first failed gate
python run_all.py 6 8 9 91   # individual stages, if their inputs already exist
```

Stages 0–3 are **gates**. Stage 0 asserts the semantic invariants the whole study rests
on — that no hidden fault information can reach the controller, that physical thrust
follows true attitude, that both execution paths consume the hidden fault slot at the same
point, that every transmitted command is attributable to exactly one declared source, and
that the interval enclosures survive sampling. Stages 1–3 hold the simulator to the
measured hardware envelopes (achieved acceleration, tracking RMSE, estimator error,
occluded error). Nothing downstream is quotable unless they pass, so the runner exits
nonzero on the first failure. Each of these gates has caught a real defect.

| Stage | Script | Produces | Approx |
|---|---|---|---|
| 0 | `stage0_semantics.py` | **gate:** 18 semantic invariants (information boundary, physics, selection, enclosures) | 1 min |
| 1 | `stage1_openloop.py` | plant, allocator, duty law, fault injection (29 checks) | 1 min |
| 2 | `stage2_anchor.py` | **gate:** closed-loop hardware anchoring | 1 min |
| 3 | `stage3_estimator.py` | estimator surrogate fit, perception degradation | 3 min |
| 5 | `stage5_data_train.py` | 360 parent episodes (160 train), 3832 probe branches, 9 trained models | 70 min |
| 6 | `stage6_methods.py` | calibration and the 3840-episode comparison grid | 18 min |
| 7 | `stage7_certificate.py` | certificate LMIs, interval verification, authority sweep | 7 min |
| 8 | `stage8_horizon.py` | horizon axis (both candidate N), OOD stress, model-level metrics | 8 min |
| 9 | `stage9_figures.py`, `stage9_writeup.py` | 7 figures and `results/results.md` | 1 min |

`data/` (generated episodes and checkpoints) is not tracked; Stage 5 regenerates it.
Stages 6–9 need it, so a fresh clone must run Stage 5 first.

## Layout

```
scsim/          plant, allocator, duty law, estimator, MPC variants,
                context model, controllers, certificate, scenarios, config
stage*.py       one script per stage, each writing a frozen JSON artefact
run_all.py      ordered runner with gate semantics
results/        artefacts, run logs, figures, and results.md
```

## Reproducibility

Scenario draws are seeded by CRC32 of the draw key rather than Python's per-process
salted `hash`, so a re-run reproduces stored values to nine decimals. For a given
(condition, episode seed) every controller sees an identical reference, disturbance,
plant mismatch, estimator noise realisation and onset time — trajectories diverge only
through the control. The recovery tolerance, eligibility radius and acceptance allowance
are frozen on a calibration split that is disjoint from the test split.
